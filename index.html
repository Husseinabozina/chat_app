THE PRODUCT IDEA

Less noise. More meaning.

A deliberately focused messenger. The planned product journey centres on finding people, connecting one to one and making each message feel clear and calm.

01 / DISCOVER
⌕✳

Find your people.

Search, discover profiles and start a conversation without the clutter of a social feed.

Approved product scope · future mobile UI
02 / CONNECT
hello!hey there ✨

Legacy Firebase messaging works · new flow planned

✦

A softer digital space.

Warm surfaces, simple navigation and a friendly interface that stays out of the way.

Visual direction approved · implementation pending

UNDER THE SURFACE

Built with intention.
Documented with care.

A monorepo separates a Flutter mobile client, a NestJS REST service and the design/product decisions that guide the work. Here's what's actually in place today.

F

Flutter mobile

Feature-first presentation, domain contracts, Cubit and a working legacy Firebase-backed chat flow.

Existing client
↔integration pending
N

NestJS REST API

Auth, discovery, direct conversations, durable text messages, read pointers and message lifecycle endpoints.

Backend implemented
↓
▤

PostgreSQL

Explicit migrations, durable data, authorization checks and integration-tested REST behaviour.

Integrated with API
TECHNICAL BOUNDARYREST + Postgres = durable source of truth.

The Socket.IO transport is approved in documentation, but it is not implemented in the current backend or active Flutter client.

QUALITY & REVIEWTwo CI pipelines, independent checks.

Flutter format, analyze and tests; backend formatting, lint, typecheck, build, migrations and E2E checks.
